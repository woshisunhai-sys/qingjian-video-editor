# 全局参考图 → 分镜首帧 → MiniMax H3｜短剧自动化技能

## 任务定位

本技能负责**资产提取之后**的镜头生产，不重新做剧本分析、不重写已确认的分镜、不重新抽取已有资产。优先使用用户当前项目中的分镜、角色、场景、道具和既有软件接口。保留上游已有的分镜 JSON（包括其既定字段）；额外创建下游运行计划 `run_plan.json`，不要擅自覆盖原分镜格式。

**唯一默认生产链**：

`已确认分镜 + CURRENT_ASSET_LIBRARY` → `位置编辑器（场景图 + 角色/道具参考图 + 坐标/朝向/姿势）` → `全局参考图 G(scene,version)` → `GPT Image 2 生成各镜头首帧` → `MiniMax H3 I2VA 首帧生视频` → `质检/截取/输出`。

## 不可违反的规则

1. **位置编辑器只用于新建/更新全局参考图**。禁止为每个分镜生成单独的“位置参考图”“站位草图”“位置引导图”。
2. 每个镜头只有一份**当前场景状态版本的全局参考图**作为空间/布景基准；分镜首帧直接从该图派生，机位/景别/构图由文字和保存的空间数据约束。可以附加角色四视图、服装或道具原始资产以修复细节，但**不允许重新引入逐镜位置参考图**。
3. 全局图不是每镜重画：相同地点且**持久性场景状态不变**时复用同一版本；持久性变化时，基于上一版本经位置编辑器**局部更新**，生成新版本。换了物理场景则建立该场景的全局图。
4. 状态变化包括：人物移到新位置、持续性坐/站/躺变化、人物/重要道具朝向与摆放变化、门窗开关、重要物体增减、衣着或布景的持续变化。**表情、瞬间抬手、眨眼、摄影机角度、景别变化**本身不触发新全局图；如果姿势/朝向变化只在镜内短暂出现且恢复原状，也不触发。
5. 为连续镜头保留 `start_state → main_action → end_state`。发生状态转换的镜头：其首帧使用**转换前**全局图，后续镜头使用**转换后**全局图。新全局图来自剧情规划的目标状态，**不强制截上一镜尾帧**，也不能把偶然生成错误当成剧情事实。
6. **默认视频模式一律 `I2VA`**：每次只给 H3 分镜首帧 + 视频提示词。禁止主动改成 T2VA、Ref2VA、尾帧生视频或 FL2VA。仅当用户/项目明确启用 `allow_fl2va_fallback=true` 且同一镜头 I2VA 已失败时，才允许单镜改走首尾帧补救；默认关闭。
7. 本技能生成的 H3 提示词：**英文结构化描述、保留原中文台词**；严格区分对白、旁白、内心独白。内心独白和旁白是画外音，不允许误变为角色对口说话。无需将整集 BGM 注入每段视频（默认 `non_diegetic_music: none`）。
8. 允许已经具备输入的无依赖分镜**批量并行提交**，不等待前一个视频结束；涉及新状态的分镜必须先完成对应全局图和首帧的依赖。提交失败按项目重试设置处理，仍失败则跳过并记录，不阻塞独立分镜。
9. **不得假装生成成功**。缺素材、缺位置编辑器能力、缺 GPT Image 2 或 H3 调用接口时输出可执行的计划/提示词/等待项；不能伪造图片、任务 ID、视频或质检结果。

## 执行流程

### 0. 读取输入并检查（只读已有资产）

- 读取已确认分镜的镜头顺序、剧情、台词、起止状态、时长和场景 ID；一个镜头只属于一个场景。
- 读取 `CURRENT_ASSET_LIBRARY`：场景图、角色参考（优先四视图/服装状态）、道具参考和已有状态版本；不因启动技能而重新提取资产。
- 读取当前工具能力：位置编辑器是否能导出布局/背景草图；图像编辑是否能使用参考图；H3 是否支持 I2VA 异步任务与状态查询。接口以项目实际能力为准，不能臆造 API。
- 若源数据不完整，标出具体缺失 ID 和所需动作；能完成的镜头继续，不能完成的镜头标记 `blocked`。

### 1. 先规划场景状态版本（逻辑层）

按剧本时间顺序建立每个物理场景的 `scene_id`、连续版本 `v1/v2/...` 和从旧版本到新版本的 `delta`。状态记录至少包括：

- 角色：`character_id`、位置 `(x,y)`（使用编辑器统一坐标系）、朝向、姿势、出入场、服装状态。
- 道具：`prop_id`、位置、朝向、持有者、开启/损坏/存在等关键状态。
- 布景：房间结构、门窗/家具及其稳定关系、光照/时间等持续变化。
- 摄影空间：场景平面布局、门窗方位、可见墙面、轴线与可能的反打方向；此为保存的数据，不是每镜单独生成的位置图。

生成清晰的“镜头使用哪个**输入状态**、镜头结束后成为哪个**输出状态**”映射。**先完成逻辑规划**再排队图片/视频，避免把全部镜头串行绑定在上一段视频完成事件上。

### 2. 位置编辑器生成/更新全局参考图

初次进入场景：导入 **当前场景图 + 角色参考图 + 道具参考图**，按状态 `v1` 在编辑器放置位置、朝向、姿势及道具，再将编辑器结果作为布局指导提交 GPT Image 2 的图像编辑/参考生图能力，获得**一张正式场景全局参考图**。

场景持久性状态变化：沿用上个正式全局图和原场景资产，位置编辑器只修改有变化的对象与局部区域，再生成下一版本（`v2`...）。保留未变背景、家具、比例、服装、人物外貌、光线与镜头轴线。为每版记录 `parent_state_id`、变更原因、编辑器布局数据、全局图路径、质检结果。

除非场景视角存在不可消除的遮挡/背后空间不确定性，**每个状态仅维护一张主全局图**。极端反打可增加同状态的“全局场景补充视角资产”，但不得退化成每个镜头额外生成位置图；优先读取既有平面布局和场景参考。

### 3. 从全局图直接生成每镜首帧

- 输入：当前 `global_state_in` 所对应的**全局参考图**、当前镜头剧情起点、机位/视角/景别/构图、必要时原始角色/道具资产。
- 输出：**一个真正适合该镜头的静态视频首帧**（可为近景、特写、反打、俯拍等）；无需也不得先创建新的分镜位置参考图。
- 遵守空间：人物左右/距离/朝向、门窗墙面、道具归属须与全局图和编辑器保存的状态一致。镜头是特写时不强迫显示全场，但出现的背景必须正确；不确定的不可见背景不能凭空固定为事实。
- **仅表现动作开始的状态**：禁止在首帧提前完成本镜头的动作或提前暴露下一镜的剧情。
- 先用中文检查资产与空间约束，再生成清晰的图像编辑指令；具体模板参见 `references/prompts.md`。
- 首帧校验失败仅重做首帧，不应无故重建整个场景全局图。

### 4. 用 H3 统一生成 I2VA 视频

- 对每个合格首帧制作 MiniMax H3 I2VA 提示词。视频从首帧 0.00 秒开始连续发展，只写本镜头应有动作、表情、运镜、声音、对白/画外音和结束状态，禁止跨镜头抢戏。
- 默认使用官方 keyframe/I2VA 风格的**三字段**结构，见 `references/prompts.md`，并在具备官方 `h3-prompt-writing` skill 时优先应用其 I2VA 规范；不要启用 Ref2VA 规则。
- 具体 API 的时长/分辨率/字段从已连接的提供方能力读取。官方 H3 常见生成任务时长为整数 4–15 秒：若计划成片只需要 1–3 秒，先生成受支持的片段再在剪辑阶段**取有效部分**；较长单镜按自然动作拆成多个生成任务。不要把分镜文字里的 1–60 秒当作所有 H3 单次任务都能接受。
- 任务队列：就绪镜头并行提交、异步轮询/回调查询；保存 `task_id`、输入图片版本、提示词版本、参数、重试计数。接口故障重试应可去重，避免重复付费。

### 5. 检验、补救、剪辑交付

逐镜检查：首帧吻合、角色身份和服装、位置/视线关系、动作起止、口型归属、旁白/内心独白不误口播、背景、道具状态、节奏、是否有可用片段。

判定：`accepted`（可直接用）/ `trim`（截取有效段）/ `retry_i2va`（同一模式优化重试）/ `skipped`（失败跳过）/ `manual_review`（影响剧情连续性，需要人工处理）。

I2VA 失败 → 最多按项目允许次数重试 I2VA → 可选单镜 FL2VA 补救（**默认关闭**）→ 标记跳过并让其他镜头继续。若跳过的是转场关键镜头，仍按**剧本目标状态**创建下一全局图，但必须标出“缺失转场镜头”的连续性风险，不能假装已表现转场。

整集成片阶段才处理统一字幕、配音修补/混音、BGM、变速、剪辑和合成；不把每段视频未经筛选整段拼接。

## 决策速查

| 变化 | 更新全局图？ | 是否生成镜头独立位置参考图？ |
|---|---|---|
| 同一站位，切近景/特写/反打 | 否 | 绝不 |
| 表情变化、暂时抬手且恢复 | 否 | 绝不 |
| 角色从门口走到沙发并停下 | 是，镜头结束后新建 `v2` | 绝不 |
| 女主从坐姿变为持续站立 | 是，生成新版本 | 绝不 |
| 门被打开并保持开启 | 是，生成新版本 | 绝不 |
| 角色离开该房间，切换到走廊 | 是，切换/建立走廊全局图 | 绝不 |

## 每次运行应交付什么

按当前用户请求的阶段，仅交付对应内容，**不要越级乱生成**。如用户只要求规划，则只给状态清单和运行计划；如用户明确要求执行且接口可用，继续生产。

1. `scene_state_manifest`：场景状态版本、编辑器布局、全局图引用、变更原因与复用关系。
2. `shot_generation_plan`：每镜引用的**全局图版本**、首帧提示词/实际文件、I2VA 提示词、生成时长、目标剪辑时长、任务依赖、状态。
3. `task_manifest`：图片/视频任务 ID、开始/结束、重试、错误、结果路径、质检与剪辑建议。
4. 如果没有真实媒体接口，则输出明确的 `planned/blocked`，不可声明已完成媒体生成。

运行计划结构、示例及合法性检查：见 `references/run_plan_spec.md`、`examples/example_run_plan.json`、`scripts/validate_run_plan.py`。适配现有客户端接口的建议：见 `references/integration.md`。

## 自检清单（交付前必须逐项确认）

- [ ] 位置编辑器只参与全局参考图的建立/更新。
- [ ] 没有为单镜头新增位置参考图。
- [ ] 相同场景状态复用全局图，持续变化才产生新版本。
- [ ] 变化镜头从旧状态开始，下一镜从新状态开始。
- [ ] 首帧没有提前完成本镜动作；反打背景与场景布局一致。
- [ ] 每个视频任务都是 `I2VA`，首帧文件对应正确全局图版本。
- [ ] 台词原文保留，旁白/内心独白与口播区分。
- [ ] 没有虚构任何生成文件、任务 ID 或质检结果。
- [ ] 失败可跳过，关键转场缺失被明确标出，不阻塞独立任务。
